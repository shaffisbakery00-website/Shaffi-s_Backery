# Shaffi's Backery — Digital Menu + Admin Dashboard: Design Spec

**Date:** 2026-10-15
**Status:** Approved by user (all sections presented and confirmed; user waived further approval gates)

## 1. Goal

A production-ready, mobile-first digital menu website for Shaffi's Backery with a
separate admin dashboard. Customers scan a QR code (QR generated by the owner from
the final URL — not by the app) and browse the menu with no login. The owner manages
sections, dishes, ad images, and review removal from `/admin`.

Explicit non-goals: cart, ordering, checkout, payments, delivery, accounts for
customers, invented business details (address/hours/phone), fake social links.

## 2. Decisions (from user Q&A)

| Topic | Decision |
|---|---|
| Database | Supabase Postgres (existing project `yurjmjazthqwxoqzkhwj`) |
| Image storage | Supabase Storage bucket — public read, writes only via server |
| Hosting | Vercel (Express wrapped with `serverless-http`); owner generates own QR |
| Initial content | Fully empty database; both empty states must shine |
| "Real time" | Fetch on load + refetch on tab focus + 30 s poll while visible (ETag/304); admin edits appear on open menus within ≤30 s |
| Reviews | **Visitor-submitted**: anyone scrolls below the menu, taps "Share a review", enters text + 1–5 stars; appears in the looping reviews scroll immediately; admin can delete any review with confirmation |
| Ads | Admin-uploaded images shown as a looping horizontal marquee strip ("Offers & Announcements") below the menu |
| Approach | A: one Express app, dual-mode (local long-lived server, Vercel serverless wrapper) |
| Approval gates | User requested no further approvals — build and verify end-to-end |

## 3. Visual identity

- Colors: warm white `#FFFEFA` (bg), deep forest green `#174C38` (brand/headings/actions),
  muted sage `#E8F0E9` (subtle bg/accents), champagne gold `#C6A15B` (sparingly: badges,
  hairlines, decorative rules — never body text on white), dark charcoal `#292D29` (text),
  soft gray `#777B75` (secondary text).
- Fonts (Google Fonts): **Cormorant Garamond** (headings, brand, review quotes),
  **DM Sans** (everything functional).
- Aesthetic: modern artisan bakery meets premium café. Generous whitespace, subtle
  rounded corners (12–16 px), gold hairline separators, smooth subtle transitions,
  no excessive gradients, no glassmorphism, no oversized animations, no clutter.
- Mobile-first: designed at 360–430 px, usable from 320 px; ≥640 px tablet,
  ≥1024 px desktop; 44 px minimum touch targets; no horizontal overflow.

## 4. Architecture

```
shaffis-backery/
├── public/                # static only — no secrets
│   ├── index.html         # customer menu
│   ├── admin/index.html   # admin SPA (hash-routed views)
│   ├── css/ tokens.css customer.css admin.css
│   ├── js/ customer.js admin.js
│   └── images/            # svg ornaments / fallback art
├── server/
│   ├── app.js             # Express app factory (shared)
│   ├── dev.js             # local long-lived listener
│   ├── config.js          # env validation & exports
│   ├── db.js              # pg Pool (pooled Supabase connection)
│   ├── auth.js            # password verify, session create/verify/destroy
│   ├── validate.js        # input validation helpers
│   ├── images.js          # magic-byte sniffing, upload/remove in Supabase Storage
│   ├── ratelimit.js       # DB-backed fixed-window limiter (login, review)
│   ├── routes/ menu.js reviews.js auth.js dishes.js sections.js admin.js
│   └── middleware/ requireAdmin.js
├── api/index.js           # Vercel entry: serverless-http(app)
├── vercel.json            # rewrites /api/* → function; static from public/
├── .env.example           # placeholders only
├── .gitignore             # ignores .env, node_modules, uploads, db files
├── package.json           # start = node server/dev.js
└── README.md              # setup, env, deploy (Vercel), DB, QR instructions
```

- Locally Express serves `public/` statically and `/api/*` itself — identical paths
  to production, so refresh and deep links (`/admin`) work in both.
- On Vercel: static files served by CDN; `/api/*` rewritten to the serverless function.
- All mutable state (menu, sessions, rate-limit windows) lives in Postgres.

## 5. Data model (Supabase Postgres, uuid PKs, RLS enabled, service-role access server-side)

- `sections(id, name text NOT NULL, display_order int NOT NULL DEFAULT 0, created_at, updated_at)`
- `dishes(id, section_id → sections ON DELETE RESTRICT, name text NOT NULL,
  description text, price numeric(10,2) CHECK (price >= 0), image_path text,
  is_popular bool DEFAULT false, is_available bool DEFAULT true, created_at, updated_at)`
  - indexes: `(section_id)`, `(updated_at DESC)`
- `reviews(id, author_name text NOT NULL, content text NOT NULL, rating int CHECK 1..5,
  created_at)` — visitor-submitted, newest first
- `ads(id, image_path text NOT NULL, is_active bool DEFAULT true, created_at)`
- `sessions(id, token_hash text UNIQUE NOT NULL, created_at, expires_at, last_seen_at)`
- `rate_events(id, action text, ip text, created_at)` — index `(action, ip, created_at)`

RLS enabled on all tables; anonymous role may SELECT only (public menu data);
all writes happen through the server with the service-role key.

Storage bucket `menu-images`: public read; writes only server-side. Object keys:
`dishes/<uuid>_<ts>.<ext>`, `ads/<uuid>_<ts>.<ext>`. Stored `image_path` is the object
key; public URL is built at response time (bucket/domain changes never break rows).

### Section deletion policy
A section with dishes can never be silently deleted. DB enforces `ON DELETE RESTRICT`;
the UI dialog shows the dish count and requires either (a) choosing a target section to
move the dishes to (single transaction: reassign + delete), or (b) cancelling. Empty
sections delete with a plain confirmation. Documented in README.

## 6. API

Public (read-only, `Cache-Control: public, max-age=0` + ETag/304 support):

```
GET  /api/menu      → { sections: [{id,name,display_order,dishes[]}], generated_at }
                      only non-empty sections; dishes ordered created_at ASC
GET  /api/reviews   → active reviews newest first (all are active; no approval flow)
GET  /api/ads       → active ads newest first
POST /api/reviews   → {author_name, content, rating, website?} JSON only,
                      Origin same-site check, honeypot, rate limit 3/hour/IP
```

Auth:

```
POST /api/auth/login     {password}  → sets HttpOnly session cookie; rate limited
                                         5 attempts / 15 min / IP; generic error text
POST /api/auth/logout                → destroys session row + clears cookie
GET  /api/auth/session               → {authenticated: bool, username}
```

Admin (all behind `requireAdmin` — session cookie verified against DB; JSON +
same-origin enforced on every mutation):

```
GET    /api/admin/stats
GET    /api/admin/dishes?q=&section_id=&availability=&popular=
POST   /api/admin/dishes            multipart (fields + optional image) or JSON
PUT    /api/admin/dishes/:id        multipart/JSON; image replace; remove_image=1
PATCH  /api/admin/dishes/:id        {is_available?|is_popular?} quick toggles
DELETE /api/admin/dishes/:id        (deletes storage image too)
GET|POST        /api/admin/sections
PUT|DELETE      /api/admin/sections/:id
POST   /api/admin/sections/:id/move {direction: up|down}   → swap display_order
POST   /api/admin/sections/reassign {from_section_id, to_section_id} (delete flow)
GET|POST        /api/admin/ads      multipart for image
PATCH|DELETE    /api/admin/ads/:id
GET|DELETE      /api/admin/reviews[/:id]
```

Validation on server for every request: trimmed non-empty names (≤80), description
≤600, price a finite number ≥ 0 (≤2 decimals), section exists, image magic-bytes
JPEG/PNG/WebP/AVIF + ≤3 MB, review content 5–500 chars, name 2–40, rating 1–5.
Parameterized queries only. Errors: `{error: "safe message"}` with proper status codes;
no stack traces/DB details ever leave the server.

## 7. Security

- `ADMIN_PASSWORD` + `SESSION_SECRET` read only server-side (env); `.env` gitignored;
  `.env.example` placeholders only; nothing sensitive in client JS or API responses.
- Login: constant-time comparison (timingSafeEqual over SHA-256 digests).
- Sessions: 32-byte random token in HttpOnly cookie (`Secure` in production,
  `SameSite=Lax`, `Path=/`); DB stores `HMAC-SHA256(token, SESSION_SECRET)` only;
  7-day rolling expiry, updated on use; logout deletes row. Nothing in
  localStorage/sessionStorage — verified.
- CSRF: SameSite=Lax + required same-origin `Origin` check + `application/json`
  requirement on admin mutations; multipart mutations also checked via Origin.
- Rate limits: login 5/15 min/IP, review 3/1 h/IP, DB-backed (works across serverless
  instances).
- Helmet-style headers set manually (CSP, X-Content-Type-Options, Referrer-Policy,
  X-Frame-Options), body size caps, storage writes exclusively server-side.
- Admin mutation endpoints return 401 without a valid session (verified by test).

## 8. Customer page (`/`)

Order: **Hero → sticky category chips → menu sections → Ads marquee → "Share a review"
button → Reviews marquee → footer.**

- **Hero:** compact (≤55vh mobile), sage arc ornament + gold wheat SVG, brand in
  Cormorant, tagline "Freshly baked, lovingly made.", one welcome sentence. No invented
  details.
- **Chips:** horizontal scroll, sticky, IntersectionObserver scroll-spy, active = green
  fill, 44 px height, hidden for empty sections, tap → smooth scroll.
- **Dish cards:** 1 col mobile / 2 col ≥640 / 3 col ≥1024, max-width 1200. 4:3 image box
  (aspect-ratio locked, lazy below fold, shimmer skeleton → SVG fallback on error, no
  CLS). Name, `₹120` (no trailing .00; paise shown only when present), clamped
  description, gold-hairline detail. Popular = gold-outline badge (dark text).
  Unavailable = desaturated image, dimmed card (~65%), "Currently unavailable" chip —
  readable, never disguised.
- **Ads marquee:** sage band, "Offers & Announcements", uploaded images as ~82vw cards,
  infinite CSS loop (list duplicated once, translateX(-50%), ~50 s, pause on
  hover/touch/focus), hidden when empty.
- **Share a review:** centered green button between ads and reviews; opens an accessible
  dialog (bottom-sheet on mobile): name, 5 large star buttons, textarea; client +
  server validation; success → dialog closes, thank-you toast, review prepended to the
  reviews marquee immediately.
- **Reviews marquee:** same loop treatment; gold quote glyph, stars, Cormorant italic
  text, author small-caps; `prefers-reduced-motion` → static horizontally scrollable
  list; hidden when empty.
- **Footer:** gold hairline, brand, "Baked fresh with love."
- **States:** loading skeletons; empty menu → "The oven is warming up" panel with
  gold-outlined croissant SVG; network error → retry panel; live refresh (load, focus,
  30 s poll).
- Accessibility: landmarks, alt text ("Photo of <dish>"), aria-labels, focus-visible,
  aria-live toasts, contrast-checked (gold never as text on white).

## 9. Admin (`/admin`)

- **Login view:** wordmark, "Welcome back", single password field + show/hide eye,
  "Sign in" with spinner, generic inline error. Username fixed server-side.
- **Shell:** top bar + slide-in drawer (mobile) / inline nav (desktop): Dashboard ·
  Menu Items · Sections · Reviews · Ads · View Customer Menu · Logout.
  Hash routing (`#/menu` etc.) so refresh/deep-links work on static hosting.
- **Dashboard:** "Welcome back" + 4 real stat tiles (Sections, Dishes, Available,
  Popular) + **Add dish** and **Manage sections** actions + Recently updated list with
  inline toggles.
- **Menu Items:** search + section/availability/popular filters; mobile = cards,
  desktop = table; one-tap Available/Popular switches (optimistic, rollback + toast on
  rejection); edit/delete with confirm.
- **Dish form (reusable add/edit):** name\*, price\* (₹, ≥0), section\*, description,
  image upload with preview/replace/remove (client downscale to ≤1280 px WebP/JPEG
  before upload), Available default ON, Popular default OFF; field-level errors,
  disabled submit while saving, data preserved on failure, toast + refresh on success.
- **Sections:** list with dish counts, inline add/edit name, ↑↓ reorder (drives chip
  order), delete → move-dishes-or-cancel dialog (or plain confirm if empty).
- **Reviews:** list of visitor reviews (stars, name, text, date) + delete with
  confirmation. No admin creation flow (visitors submit).
- **Ads:** upload with preview, list thumbnails, active toggle, delete with confirm.
- **Feedback everywhere:** toasts (success/error), button spinners, confirm dialogs,
  rollback on server rejection.

## 10. Performance (100 concurrent scanners)

Static shell from Vercel CDN; menu = one small JSON (ETag → 304 on polls); images from
Supabase CDN with immutable cache headers (`?v=<updated_at>` cache-busting on replace);
vanilla JS, no frameworks; lazy images + aspect-ratio boxes; gzip on; pooled Postgres
connections (port 6543) with small indexed queries; reviews/ads fetched once + on
focus. 100 concurrent visitors ≈ CDN hits + a handful of tiny queries — far below free
tier limits.

## 11. Testing & verification (must pass before completion)

The spec's 17-point checklist: public menu without login; data from DB; login works;
wrong password rejected; unauthenticated mutation → 401; dish CRUD; image
upload/replace/remove; toggles persist; sections create/edit; section delete safety;
customer reflects admin changes; data survives restart; refresh works; narrow mobile
(320–430 px) usable; no credentials in repo/client assets; plus review submit →
appears in scroll → admin deletes it; ad upload → appears in strip.

Method: run server locally, exercise API with curl (auth matrix), click through both
UIs with Playwright at mobile viewport, grep repo for secrets, `node --check` all JS.
